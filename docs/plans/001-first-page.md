## Risks and what could break

- **Riskiest step: the first real deploy.** `deploy.yml` uses an environment named `production`; `docs/GAPS.md` notes `actions/deploy-pages` may require `github-pages`. We find out when the owner approves the deploy. If it fails, the fix is a workflow edit (rule 4 PR) and does not touch this PR.
- **Node version.** Astro 7 refuses Node < 22.22. Local needs the nvm step; CI resolves `22` to 22.23.x. If `npm ci` in CI complains about engines, pin `node-version: 22.23.3` in a rule 4 PR.
- **`astro preview` and the base path.** Preview serves under `/sdlc-mvt/`; the smoke test URL assumes it. If preview serves at `/` instead, the `webServer.url` and `baseURL` change and nothing else.
- **Lockfile drift.** `npm ci` in CI fails if `package-lock.json` is out of step with `package.json`. Generated once with npm 10 locally; CI's Node 22 ships npm 10.
- **TypeScript 7.** `@astrojs/check` peers on TS 5 or 6, so the plan pins `^5.9.3` even though 7.0.2 is latest. Noted in the PR dependency lines.
- **Placeholder copy goes live.** Owner's decision; the bracketed text makes it obvious and the content PR follows.

## Options not taken

- `withastro/action` for deploy: would replace the existing gated `deploy.yml`; we keep the human gate.
- ESLint plus plugins for lint: three or four more dependencies for one page; `astro check` covers templates and types.
- Astro content collections for the copy: overkill for four strings; a JSON file keeps content PRs trivially content-only.
- Splitting toolchain and page into two PRs: CI would be red in between (no page to build); owner waived rule 11 instead.
- Shipping real copy now: owner chose placeholders.

## Departures from plan

- Added `vitest.config.ts`. Vitest's default include pattern picked up `e2e/smoke.spec.ts` and failed on the Playwright import; the config scopes Vitest to `src/**/*.test.ts`.
- `playwright.config.ts` web server command ends with `--ignore-lock`. Astro 7's `astro preview` writes a lock file and refuses to start while one exists, which left Playwright's server step reporting an early exit after the first run.
- Added `@types/node` (sixth dev dependency, no new file). `astro check` type-checks `playwright.config.ts`, which reads `process.env.CI`, and fails without Node's type definitions.
