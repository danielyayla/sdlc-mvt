# Gaps

Things the playbook recommends that GitHub free tier plus Claude Code alone cannot do, or can only approximate. Each bullet says what the playbook wants, what we do instead, and what would close the gap.

- **Managed Code Review service.** Playbook: enable the hosted reviewer as an admin. Here: `claude.yml` runs `claude-code-action` in our own CI. It needs an `ANTHROPIC_API_KEY` repo secret, which is Anthropic billing, not GitHub free. Until the secret exists the review job fails and the PR shows a red check that is not a required check.
- **Separation of duties with one maintainer.** Playbook: branch protection requires a code owner's approval. Here: GitHub will not let the PR author approve their own PR, so protection on `main` requires green checks and a PR but zero approvals; the human gate is the owner clicking merge. PRs authored by the action (bot identity) can require the owner's approval later.
- **Managed settings for non-negotiable hooks.** Playbook: IT-owned settings engineers cannot switch off. Here: hooks live in `.claude/settings.json` in the repo and a session could edit them. Backstops: POLICY rule 4, CODEOWNERS on `.claude/`, and the review calling such edits Important.
- **Statistical control bands (1σ/2σ/3σ, Western Electric rules).** Playbook: a deterministic script over a rolling baseline. Here: one URL has no baseline, so `monitor.yml` is binary up/down with retries. A `bands.yaml` makes sense once there is a metric with history (e.g. CI failure rate).
- **Scheduled workflows go to sleep.** GitHub disables cron workflows after 60 days without repo activity. The monitor stops silently. Any commit re-enables it.
- **Deploy and rollback as MCP tools.** Playbook: deploy, status, rollback exposed as scoped tools. Here: deploy is a workflow gated on the `production` environment; Pages has no rollback API, so rollback is a revert PR plus redeploy, and that path has not been rehearsed yet.
- **Sandboxed agent execution with a network policy and short-lived tokens.** Here: GitHub-hosted runners with the default `GITHUB_TOKEN` scoped per job. No egress policy.
- **Claude Design, Claude Security, Claude Tag (Slack on-call).** Not available in this setup. Design iteration happens in a Claude Code session with a browser; security scanning is limited to review passes; incidents arrive only via the monitor Issue.
- **Organization-level slash commands and skills.** Single repo, so any commands or skills would live under `.claude/` here rather than be distributed.
- **Continuous evals in CI on every CLAUDE.md, hook or policy change.** Here: `evals/run.sh` runs locally against the logged-in `claude` CLI to avoid API spend. Wiring it as a CI job on `paths: [CLAUDE.md, POLICY.md, .claude/**]` is a small addition once the secret exists and the suite is bigger.
- **Custom environment name for Pages.** `deploy.yml` uses an environment named `production` so the required reviewer sits there. If `actions/deploy-pages` rejects a non-default environment on the first real deploy, rename it to `github-pages` and move the reviewer.
- **Intent home writable by non-engineers via a connector.** Playbook: a GitHub connector lets contributors commit `intent.md` from claude.ai. Here: the Issue form (`.github/ISSUE_TEMPLATE/intent.yml`) is the non-git route; someone with git copies the accepted Issue into `intents/`.
- **The pipeline cannot review the PR that creates it.** `claude-code-action` skips itself when the workflow file on the PR differs from the copy on `main` (its own supply-chain guard), so PR #1 shows `review` as passed without a comment. The same applies to any later PR that edits `claude.yml`: that PR gets a human-only review, which matches POLICY rule 4 anyway. The action starts reviewing on the first PR after this one merges.
